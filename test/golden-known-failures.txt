# Test ROMs that Ocelot is currently known to fail.
#
# The golden suite reports accuracy gaps as pending rather than failing, so the run stays green and
# the gap list stays visible. On its own that means a ROM sliding from passing to failing shows up
# only as a changed pending entry somebody has to spot in a diff. This file makes it a ratchet:
#
#   * A ROM not listed here MUST pass. If it fails, the suite fails and names it a regression.
#   * A ROM listed here that starts passing ALSO fails the suite, asking you to delete its line.
#
# Both directions are deliberate. Silent movement either way is what let two regressions through
# before this file existed.
#
# Paths are repo-relative and must match the ROM path the spec loads. Blank lines and lines starting
# with '#' are ignored. Keep entries sorted so the diff reads cleanly.
#
# Run the golden suite with: OCELOT_GOLDEN=1 stack test

# The nine instruction-timing ROMs (add_sp_e, ld_hl_sp_e, call, call_cc, ret, ret_cc, reti, jp,
# jp_cc) used to live here. They were never timing failures: OAM DMA locked the CPU off every
# address below 0xFF00, so an instruction fetch from WRAM or echo RAM read 0xFF, decoded as RST 38h,
# and wedged at PC=0x38. Modelling the DMA conflict per-bus fixed all nine at once.
